# 非公開の開発者用ページ

GitHub Pages側にはこのページのHTMLやパスワード照合処理を含めません。開発者用ボタンから独立したCloudflare Workerに移動し、サーバー側でパスワードを確認した後に部位追加のGUIを配信します。認証前に `/developer` へ直接アクセスしてもログイン画面へ戻ります。

現在は共通パスワードによる認証です。正解のパスワードはCloudflareのSecretに保存し、ブラウザや公開リポジトリへ配信しません。認証後は4時間有効な署名付きCookie（HttpOnly・Secure）を使い、パスワードまたは署名用Secretを変更すると既存のCookieも無効になります。ログアウトはそのブラウザのCookieを削除します。失敗を含むログイン試行は接続元IPごとに1分5回までです（Cloudflareのレート制限は拠点ごと・ベストエフォート）。

認証・画像作成・保存・GUIの調整値は [`src/config.js`](../src/config.js) で一括管理しています。以下の文字数・時間・画像枚数は初期値です。変更方法は [ルートREADMEの「定数・制限の変更」](../README.md#定数制限の変更) を参照してください。

通常画面・ログイン画面・開発者画面の右上でライト／ダークモードを切り替えられます。選択はブラウザーに保存され、画面間の移動時にも引き継がれます。配色は `src/theme.css`、保存・引き継ぎは `src/theme.js` を共有しています。この2つの共通表示ファイルはログイン前にも読み込めます。編集画面や保存APIには引き続き認証が必要です。

## ローカルで確認

リポジトリのルートで実行します。

```sh
npm ci --prefix developer
npm run dev
```

`http://localhost:8787/` を開きます。生成された `developer/.dev.vars` の `DEVELOPER_PASSWORD` の値でログインできます。このファイルはGitの管理対象外で、スクリプトを再実行しても上書きしません。パスワードと署名用 `SESSION_SECRET` は、`src/config.js` の `AUTH` で指定した最低文字数を満たす値を使います。

通常の `npm run dev` で認証サーバーとViteを同時に起動し、ボタンも自動的にローカル版へ接続します。`.env.local` の設定は不要です。通常の操作はルートの `npm run dev:status` / `npm run dev:stop` / `npm run dev:restart` で管理します。`.dev.vars` の変更は自動で読み直します。詳細は [ルートREADMEの操作表](../README.md#初回の準備と日常の操作) を参照してください。

認証サーバーだけを起動する場合は `npm run dev --prefix developer` を使用します（同じ管理プロセスを使い、二重起動はしません）。この場合、戻り先は `http://localhost:5173/echo_training-App/` です。このローカル接続先は公開ビルドには含めません。

## Cloudflareへの公開

CloudflareアカウントとWorkers Freeプランを使います。アカウント作成・ログインは利用者本人が行ってください。現在のFreeプランは期限付きの試用ではなく、1日10万リクエストなどの上限があります。料金・上限は将来変更される可能性があります。

```sh
cd developer
npx wrangler login
npm run deploy
npx wrangler secret put DEVELOPER_PASSWORD
npx wrangler secret put SESSION_SECRET
```

2つの `secret put` は対話入力です。パスワードなどをコマンド引数、ソースコード、`wrangler.jsonc` の `vars` に書かないでください。公開用には別のランダムなパスワードと署名用Secretを用意できます。設定が揃うまではWorkerが503を返し、開発者画面も配信しません。パスワードの変更は同じ `secret put` コマンドで行えます。

公開後、表示された `https://echo-training-developer.<サブドメイン>.workers.dev/` を使って接続します。

- GitHubリポジトリの **Settings → Secrets and variables → Actions → Variables** に `DEVELOPER_URL` を追加し、公開URLを値に設定します。パスワードの登録は不要です。
- GitHub Pagesのワークフローを再実行します。
- ローカルから公開版に接続する場合も、ルートの `.env.local` の `VITE_DEVELOPER_URL` を公開URLに変更してViteを再起動します。

CloudflareアカウントやSecretはリポジトリ作成だけでは設定されません。公開URLが未設定の公開サイトでは、開発者用ボタンから「接続準備中」の画面を表示します。

## 部位を追加する

設定は「部位と動画」「人体とカメラ」「プローブ」のタブで切り替えます。PCでは人体・エコー画像・保存操作を同じ画面内に表示し、タブを切り替えても入力は保持します。スマートフォンでは読みやすさを優先して縦に並べます。

1. 部位のカテゴリー・名前を入力し、MP4を選びます。
2. 「動画から200枚の画像を作成」を押します。エコーと人体写真が並んだ動画の場合は「動画の左から使用する幅」を先に調整します。画像は最大辺960pxのJPEGで、動画全体から等間隔に抽出します。元の動画はアップロードしません。
3. 男性・女性、ポーズ、部位選択で表示する面を選びます。
4. 人体をドラッグしてカメラを回転、ホイールで拡大縮小、右ドラッグで平行移動します。正面・左右側面・背面のボタンで視点を戻せます。
5. 「開始点を指定」を押して体表上の開始点、続けて終了点をクリックします。開始点と終了点のx/yを同じ欄で直接調整することもできます。
6. スライダーでエコー画像と3Dプローブの動きを確認し、「保存して部位選択に追加」を押します。200地点すべてで体表との接触を確認してから保存します。

保存後、通常画面の指定した面のリストに「＋ 部位名」が追加されます。エコー画面では保存したモデル・ポーズ・カメラ・プローブの経路を使います。画面比率が変わっても保存した縦方向の拡大率と中心を維持します。横方向に見える範囲は表示幅に応じて変わります。

カメラは開始点・終了点の指定後にも動かせます。開始点を選んだときの座標面を保持するため、視点を変えても点が体表上から移動することはありません。別の面から点を取り直したい場合は「点をクリア」を使います。モデルやポーズを変更した場合は2点を指定し直します。

新規部位は開始点から終了点への直線移動です。部位の削除・構造物の輪郭編集・傾けるタイプの走査の新規追加は含みません。

## 既存部位のカメラ・座標を変更する

1. 「既存部位を編集」に切り替え、編集する部位を選びます。最初からある11部位と、開発者ページで追加した部位の両方が対象です。
2. 現在のモデル・ポーズ・カメラ・開始点/終了点を読み込みます。「人体とカメラ」で視点を動かし、「プローブ」でx/yを入力するか体表上の点を選んで調整します。
3. 登録済みのエコー画像をスライダーで確認し、「変更を保存」を押します。動画の再登録は不要です。
4. 「変更したエコーを開く」で通常画面を確認します。既に開いている通常画面は再読み込みしてください。

「保存済みの設定を再読み込み」で、保存前の変更を戻せます。部位を切り替える前に変更を保存してください。ほかの画面で先に更新されていた場合は、その設定を読み込み直してから編集します。

既存のエコー画像、構造物の表示データ、呼吸動画、走査方式を維持します。「腹部：右肋間」「腹部：左側腹部」は傾ける走査のままで、開始点と終了点を同じ座標にすることもできます。モデル・ポーズを変更すると点はクリアされるので指定し直してください。

既存部位の変更はKVに保存し、元のソースファイルは書き換えません。通常画面は `DEVELOPER_URL` で指定したWorkerから設定を読み込み、保存された部位のカメラ・座標を優先します。ローカルの変更はローカル環境に反映され、公開環境の変更は公開用の開発者ページから行います。

## 保存先と公開範囲

- 開発者画面・モデル編集用の素材・保存APIは、引き続きパスワード認証が必要です。GitHub Pagesのビルドには開発者画面を含めません。
- 「保存して部位選択に追加」で確定した部位名・エコー画像・設定だけを、認証不要の読み取りAPIで配信します。通常画面から利用するための公開データです。
- 部位・カメラ・開始点/終了点はWorkers KVの `SCANS` にまとめて保存します。画像は10枚ずつのバイナリパックに分け、200枚が揃ってから部位を公開します。未確定アップロードは通常1日で期限切れになります。
- ローカルでは `developer/.wrangler/state/` に永続保存され、サーバーを再起動しても残ります。このディレクトリはGit管理対象外です。削除するとローカルの追加部位も失われます。
- ローカルとCloudflare上のデータは別です。ローカルで追加した部位は、デプロイだけでは公開環境へ移りません。公開用の開発者画面から追加してください。
- `wrangler.jsonc` のKVは初回デプロイ時にWranglerが作成します。作成後はWranglerの案内に従ってnamespace IDを設定に残し、以後も同じ保存先を使ってください。IDはパスワードではありません。
- Cloudflare KVの反映には時間差があるため、保存直後に別の拠点で開くと少し待って再読み込みが必要な場合があります。無料枠を超えると保存・読み取りが失敗します。利用上限は [KVの料金](https://developers.cloudflare.com/kv/platform/pricing/) を確認してください。

ソースコードが公開リポジトリにある場合、GUIの実装自体は読めます。パスワードなどの秘密情報をコードやモデルに含めないでください。

## 開発と確認

`developer/ui/` を変更したら `npm run build --prefix developer` で再ビルドし、ブラウザーを再読み込みします。通常の `npm run dev` も起動時に開発者画面をビルドします。

```sh
# リポジトリのルートから
npm test
npm run build
npm run test:e2e
npm run test:editor
npm run check --prefix developer
```

`test:editor` は8788・5175番ポートと、実行ごとにOSの一時ディレクトリに作る専用パスワード・保存先を使い、通常の `.dev.vars` やローカル追加部位と分離して、ログイン・動画変換・カメラ操作・保存・再生を実ブラウザーで検証します。`tests/fixtures/editor-test.mp4` はffmpegのtestsrcから生成したテスト動画です。Chromeを指定する場合は `PLAYWRIGHT_CHROME_PATH` を設定します。`check` は公開しないdry-runです。
