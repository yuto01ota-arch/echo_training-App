# ECHO TRAINING — 人体3Dビューアー

通常画面は React + Vite + Three.js の静的サイトです。開発者ページは、パスワードの照合と部位データの保存を行う **別のサーバー** を使います。作業・公開用ブランチは `3d-demo` です。

## どこで動くか・何に依存するか

ローカルで `npm run dev` を実行すると、**このMac内**に次の2つのサーバーを起動します。`localhost` は自分のパソコンを指します。Cloudflareへの公開やログインは行いません。

| 役割 | ローカルのURL・保存場所 | 使用するもの |
| --- | --- | --- |
| 部位選択・エコーの通常画面 | `http://localhost:5173/echo_training-App/` | Node.js上のVite。ブラウザーでReact・Three.jsを実行 |
| 開発者ページ・認証・保存API | `http://localhost:8787/` | Node.js上のWranglerと、そのローカル実行環境workerd |
| 追加部位・カメラ設定・追加した画像 | `developer/.wrangler/state/` | Workers KVをローカルで再現した保存先 |
| ローカルのパスワード・署名用Secret | `developer/.dev.vars` | このMac内のファイル。Git管理対象外 |

パスワードをブラウザーへ配らずに照合し、ページ内容を認証後に配信することと、GUIから部位データを保存するために、開発者側のサーバーを使っています。通常画面に同梱した11部位の閲覧は、静的ファイルで動きます。追加部位や変更済みの設定を読み込むときは、開発者側の読み取りAPIも使用します。

公開時は通常画面を **GitHub Pages**、開発者ページ・APIを **Cloudflare Workers**、保存先を **Cloudflare Workers KV** に置く構成です。ローカルで起動してもインターネットには公開されません。ローカルと公開先のパスワード・保存データは別で、自動同期しません。

## 初回の準備と日常の操作

Node.js 20.19以降の20系、または22.12以降と、付属のnpmを使います。初回はリポジトリのルートで依存パッケージをインストールします。

```sh
npm ci
npm ci --prefix developer
```

普段は、同じフォルダーで次のコマンドだけを使います。

| 操作 | コマンド |
| --- | --- |
| 通常画面・開発者ページをまとめて起動 | `npm run dev` |
| 起動状態・URLを確認 | `npm run dev:status` |
| 両方を停止 | `npm run dev:stop` |
| 両方を再起動 | `npm run dev:restart` |

起動コマンドを実行したターミナルは開いたままにします。そのターミナルの **Ctrl+C** でも両方を停止できます。別のターミナルからでも `dev:status` / `dev:stop` / `dev:restart` を使えます。再起動コマンドも起動状態のまま待機するので、以後はそのターミナルで管理できます。

起動済みで `npm run dev` を重ねて実行すると、起動中のURLと操作方法を表示し、二重起動しません。この管理コマンド以外で起動したサーバーが同じポートを使っているときは、黙って再利用したり終了させたりせず、ポート競合を表示します。その場合だけ、以前起動したターミナルでCtrl+Cで停止してから、上のコマンドに統一してください。

`developer/.dev.vars` の `DEVELOPER_PASSWORD` を編集して保存すると、起動中の管理コマンドが認証サーバーを自動で再起動します。完了メッセージが出たらブラウザーを再読み込みし、新しいパスワードを入力します。パスワードはログに表示しません。設定が文字数などの条件を満たさない場合は、理由をターミナルに表示して停止します。

`src/config.js` の制限や開発者画面のコードを変えたときは `npm run dev:restart` を使います。開発者画面のビルドと認証設定の読み込みからやり直します。停止・再起動で保存済みの部位は消えません。**保存データを残すには `developer/.wrangler/state/` を保持してください。**

`.env.local` の `VITE_DEVELOPER_URL` に外部URLを設定した場合は、起動時に「外部の接続先」と表示し、ローカル認証サーバーは起動しません。停止・再起動コマンドが操作するのはこのMac内で起動したプロセスだけです。

## インストールが必要なもの

- **開発・ローカル実行：** Node.js / npm、ルートと `developer/` の依存パッケージ。
- **ブラウザー：** WebGL 2を利用できるブラウザー。モデル・エコー画像は同梱素材を配信します。
- **公開：** 通常画面はGitHub / GitHub Pages。開発者ページと保存機能はCloudflare Workers / KVの設定が別途必要です。
- **テスト時のみ：** Playwrightと対応するChromeまたはChromium。
- **モデル素材の再生成時のみ：** Blender。通常の起動・サイト閲覧には不要です。

主なパッケージは [`package.json`](package.json)、開発者サーバー用は [`developer/package.json`](developer/package.json)、固定された依存バージョンはそれぞれの `package-lock.json` にあります。

```sh
npm test
npm run build
npm run preview
```

`preview` はビルド済みの通常画面だけを確認するコマンドです。日常の編集作業では `npm run dev` を使ってください。

## 機能

- Blender公式 **Human Base Meshes v1.4.1** のリアル系男性・女性モデルを表示・切り替え。
- 正面・側面・背面の3面を独立して表示。側面は身体本人の右側／左側を切り替え可能で、どちらも腕を広げた姿勢で表示します。正面・背面は選択中のポーズで表示します。
- 部位選択画面もヘッダーと説明をコンパクトに配置。PCでは3面と部位名ボタンを画面の高さに合わせて表示し、スマートフォンでは縦並びにします。
- `main` の腹部6・前腕3・右下肢2、計11項目を体表の目印・番号・部位名から選択し、対応するエコー画面へ遷移。スマートフォンでは3面を縦に配置。
- 2体に基本姿勢と腕を広げた姿勢を用意。アニメーションの再生はありません。

体表を表示するモデルです。臓器・血管などの内部構造は含みません。肌の色・細かな凹凸・艶のテクスチャを内包し、各モデルは約14〜15 MBです。選択された1体だけを読み込みます。読み込みに失敗した場合は直前のモデルを保ち、選択ボタンから再試行できます。

## エコー画面

部位をクリックすると `#/echo/abs_long` などのURLでエコー画面を開きます。GitHub Pagesのサブパスでも直接アクセス・再読み込みができ、ブラウザーの戻る／進むに対応します。「部位選択に戻る」では人体モデル、ポーズ、側面の左右を維持します（ページ全体を再読み込みした場合は初期状態）。

- エコー画面はヘッダーを小さくし、PCでは画像・モデルの右に操作欄を配置。画面の高さに合わせて画像を縦横比を保って表示します。スマートフォンでは縦並びで表示します。
- 各部位200フレーム。スライダー・前後ボタン・番号入力・プローブのドラッグ／矢印キーで切り替え。
- 構造物ボタンで元データの輪郭を重ねて表示。登録範囲外のフレームではボタンを無効化。
- 左右の側腹部ではフレーム1から呼吸動画を再生。
- 画像の読み込み失敗は再試行可能。フレームを素早く変更しても古い画像の読み込み結果を採用しません。

`src/components/EchoScanner.jsx` が画面、`src/echo/scans.js` が部位対応と補間処理です。`src/echo/source/` のメニュー・輪郭データと `public/echo/` の画像2,200枚・呼吸動画2本・プローブ画像は、同じリポジトリの `main`（`11e6c5b`）から取り込んだものです。モデルを生成した素材とはライセンスが異なり、元の著作権表記を `public/echo/NOTICE.txt` と `public/echo/LISENCE` に保持しています。画像・動画の配信データは約261 MiBですが、ブラウザーでは表示する画像と操作時の動画だけを読み込みます。これらの同梱素材の配信に外部モデルサービスやバックエンドは使いません。追加部位・保存した変更の読み込みは、上記の開発者サーバーを使用します。

### 全11部位の3Dプローブ

全11部位で人体と同じ3D空間に簡易プローブを表示します。白い本体・接触面・短いケーブルをThree.jsの形状から作成したオリジナルの試作で、実機の寸法を再現したものではありません。部位ごとの向きは `src/echo/scanPresentation.js` の設定を使います。右肋間・左側腹部では、固定した走査位置でプローブを立体的に傾けます。

開始点・終了点は `src/echo/scanPaths.js` の既存設定を使用します。x/yの移動はフレームごとの等間隔を保ち、奥行きと向きは各位置の人体表面から求めます。通常は接触面の中心を体表に合わせ、傾き操作では接触面の端を基準に高さを補正します。皮膚の押し込み変形は行いません。モデルの形状は `src/three/probe.js` で管理します。ドラッグ・タッチ・矢印キー・スライダー操作に対応し、操作時のみ再描画します。

### 全11部位の人体モデル表示

腹部6・前腕3・右下肢2の全11部位で、エコー領域と人体モデルを並べて表示します。右肋間・右側腹部は右側面、左側腹部は左側面、膝裏は背面、その他は正面を表示します。前腕・下肢では対象部位を拡大します。男女モデル・ポーズを引き継ぎ、スマートフォンでは縦に配置します。部位選択・エコー画面ともに、側面では腕が腹部を隠さないよう腕を広げます。正面・背面に使うポーズの選択は保持します。

元の合成画像・呼吸動画から人体写真を隠す切り抜き設定は `src/echo/scanPresentation.js` にあります。画像と構造物の輪郭を同じ座標系で切り抜きます。動画再生中はプローブ操作を無効化します。

**走査位置を変更するときは `src/echo/scanPaths.js` だけを編集してください。** `MODEL_SCAN_PATHS` に全部位の `start: { x, y }` / `end: { x, y }` をまとめています。「腹部：長軸」の調整済み座標は保持し、他の部位は位置調整用の初期値です。

座標は身長1.8の基本姿勢を基準とします。yは足元0から上が正です。xは各表示面の横方向で、正面は本人の左、背面は本人の右、右側面は身体の前、左側面は身体の後ろが正です。各部位の表示面は座標ファイルのコメントにも記載しています。ポーズを変更しても、指定した体表位置に追従します。

移動計算は `src/echo/probeMotion.js`、体表への対応付け・描画は `src/three/scanBody.js`、操作は `src/components/EchoBodyModel.jsx` です。`t = (frame - 1) / (frameCount - 1)` で開始点から終了点を直線補間し、1フレームあたりの移動距離を一定にします。水平・斜めのドラッグ、タッチ、矢印キーに対応します。元データが傾き操作の右肋間・左側腹部は開始点と終了点を同じ値にして、上下ドラッグで傾きを変えます。自動再生はありません。

記録済みのエコー画像と体表上の操作位置を対応させる試作です。モデルからエコー画像を生成するものではなく、撮影位置との校正は行っていません。

## モデルとポーズの拡張

部位定義は `src/three/regions.js`、選択UIは `src/components/BodyRegions.jsx` にあります。部位名・ID・対象構造はローカル `main` の `11e6c5b` にある `src/frontend/menuConfig.js` を引き継いでいます。旧画面の画像上の座標は3Dモデルに流用できないため、位置は体表上の目安として設定し、モデルごとに最寄りの頂点へ結び付けています。ポーズ変更にも追従します。前腕は元データに左右指定がないため右腕にまとめています。臨床的なプローブ位置の精度は未検証です。

部位をクリックすると対応するエコー画面へ遷移します。3面は同じThree.jsシーンを別カメラで描いた画像で、モデル・ポーズ・画面サイズの変更時に更新されます。モデルを3回ダウンロードすることや、追加のWebGLコンテキストはありません。

モデル一覧は `src/three/models.js`、ポーズ定義は `src/three/poses.js`、表示・読み込みは `src/three/viewer.js` に分離しています。元のHuman Base Meshesには骨格がなかったため、2体とも19本の基本ボーンとスキニング情報を追加しました。ポーズ定義に静的な回転を追加できます。

元の体表メッシュは **Dan Ulrich** 作の `Body Male - Realistic` / `Body Female - Realistic` です。CC0素材をGLBへ変換して同梱しているため、実行時に外部のモデル配信サービスは使用しません。出典・ライセンス・加工内容は [`public/models/NOTICE.txt`](public/models/NOTICE.txt)、編集用Blenderファイルと再生成手順は [`assets/source/`](assets/source/README.md) にあります。

肌はこのプロジェクト用のAI生成画像をもとにしたテクスチャです。実在人物の写真・スキャンではありません。目は白目・虹彩・瞳孔を別マテリアルで表現しています。生成画像・依頼文・再ベイク手順は [`assets/textures/`](assets/textures/README.md) を参照してください。テクスチャはGLBと編集用Blenderファイルに内包され、ポーズ変更に追従します。

追加した骨格は基本的な姿勢変更用です。指ごと・表情の操作や筋肉の補正は含みません。新しい姿勢では関節周囲のウェイト調整が必要になることがあります。

実際の人体モデルには、**ボーン（リグ）とスキニング情報を含むGLB** を使用してください。GLBはファイル形式であり、すべてのGLBにボーンが含まれるわけではありません。ボーンなしでも表示できますが、関節を曲げるにはBlenderなどでリグを追加する必要があります。

公開用の固定モデルを追加する際は `public/models/` に置き、`import.meta.env.BASE_URL + 'models/ファイル名.glb'` を使って読み込みます。別モデルを複数登録する方法でも、1体のリグ付きモデルにポーズを適用する方法でも拡張できます。モデルを公開する前にその素材の再配布ライセンスを確認してください。

## GitHub Pages

開発者用ボタンは、別のCloudflare Workerで認証してから非公開ページを開きます。開発者画面では動画から200枚の画像を作成し、3Dモデルの視点とプローブの開始点・終了点を設定して新しい部位を追加できます。保存した部位は指定した面のリストから開けます。「既存部位を編集」では、元からある部位と追加部位のカメラ・開始点/終了点を変更して保存できます。「この部位を削除」で確認後に削除することもできます（保存データは保持、復元画面は未実装）。パスワードはGitHub Pagesや公開コードには含めません。外部サービスの設定、ローカル確認、公開手順は [developer/README.md](developer/README.md) を参照してください。

1. GitHub のリポジトリ設定 → **Pages → Build and deployment → Source: GitHub Actions** を選択。
2. この変更を `3d-demo` ブランチに push。
3. `Deploy 3D demo to GitHub Pages` が成功したら、以下で公開されます。

https://yuto01ota-arch.github.io/echo_training-App/

`vite.config.js` の `base` はこのリポジトリ名に設定済みです。ワークフローは `3d-demo` への push でビルドし、Pages にデプロイします。GitHub Pages はリポジトリにつき1つのサイトのため、同じリポジトリで既存サイトを公開している場合、このデプロイでその内容が置き換わります。

## 定数・制限の変更

仕様や調整値は **[`src/config.js`](src/config.js)** にまとめています。各処理の数値を探して書き換える必要はありません。

| 設定 | 主な用途 |
| --- | --- |
| `AUTH` | パスワードの最低・最大文字数、セッション有効時間、入力サイズ |
| `TILT` | 新規tiltの初期角度・入力範囲・最小角度差・ドラッグ方向 |
| `FRAME_COUNT` / `PACK_SIZE` | 新規部位の画像枚数・一度に保存する枚数（保存回数は自動計算） |
| `IMAGE` | 画像の最大辺、JPEG品質、動画の待ち時間、画像の容量制限 |
| `PREFETCH` | 前後に保持する画像枚数、同時先読み数 |
| `VALIDATION` | 名前の長さ、座標・カメラ・開始点と終了点の制限 |
| `API` | 受信サイズ、一覧の件数、下書き期限、通信の待ち時間 |
| `EDITOR` / `CAMERA` | 座標入力の刻み、経路チェック、ズーム範囲など |
| `DEV_SERVER` | ローカル認証サーバーの起動待ち時間 |

単位と用途は設定ファイルのコメントに記載しています。例えばパスワードの最低文字数は `AUTH.minPasswordLength` を変更します。パスワードやSecretの**実値**は引き続き `.dev.vars` / Cloudflare Secretsで管理し、このファイルには書きません。

`FRAME_COUNT` は2以上で `PACK_SIZE` で割り切れる整数にしてください。画像枚数の表示・抽出・プローブの進行度・保存処理が追従します。保存済み部位は保存時の画像枚数とパックサイズを使います。`STORED_MEDIA` は同梱素材と旧保存形式の仕様なので、通常は変更しません。パック数を増やす場合は、公開先のリクエスト・ストレージ上限も確認してください。

変更後はローカルサーバーを再起動してください。公開環境へ反映するには、公開アプリと開発者用Workerを再ビルド・公開し、ブラウザーを再読み込みします。

人体の部位座標・ポーズ・部位別表示は既存の専用ファイルで管理します。HTTPステータスやファイル形式の固定値、CSSの見た目の数値は調整用定数に含めていません。Cloudflareのログイン回数制限はプラットフォーム設定であるため、`developer/wrangler.jsonc` の `ratelimits` で管理します。
